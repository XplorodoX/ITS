05 — Software-Struktur

Code-Aufbau & Software-Architektur

C++ 1. Firmware
src/firmware/Controller

main.cpp

Initialisierung und Haupt-Loop (Superloop). Verteilt Events je nach Spielzustand an die Untermodule.

display.cpp

Umfasst alle showState()-Renderfunktionen zur pixelgenauen OLED-Zeichnung im Hauptloop.

network.cpp

Verwaltet die WiFi-Verbindung und die blockierungsfreie MQTT-Reconnect-Schleife.

Py 2. Game Master / API
src/backend

game.py (GameMaster)

Zentrale Logik-Klasse. Verwaltet Spielerlisten, MQTT-Events und die State Machine des Quizzes.

scoring.py

Berechnet Punkte in Echtzeit: Punkte = Basis (1000) + Zeitbonus (max. 500) × Streak-Bonus.

app.py (Flask API)

Stellt REST-Endpoints bereit, über die das Admin-Frontend Fragensets laden und aktivieren kann.

TS 3. Frontend
src/frontend

Beamer-View (page.tsx)

Die Projektionsfläche der Lobby, Frageseiten und des Leaderboards für die gesamte Klasse.

Admin-Panel (/admin)

Erlaubt dem Spielleiter, den Ablauf manuell zu triggern, Fragensets hochzuladen und Spieler zu verwalten.

mqtt.js Integration

Abonniert den Broker direkt im Browser über WebSockets (Port 9001), um sofort auf Zustandsänderungen zu reagieren.

10 — Herausforderungen

Probleme & Lösungen

01

Echtzeit-Sync aller Controller

Problem

Mehrere ESP8266 müssen exakt denselben Spielzustand zeigen — ohne zentrale Taktung

Lösung

State Machine publiziert Spielzustand — Controller reagieren rein event-getrieben

quiz/state
02

Namenseingabe ohne Tastatur

Problem

Gerät hat nur Drehgeber + Taster + 128×64 OLED — kein Keyboard

Lösung

Scroll-Liste per Encoder, Bestätigen per Klick — Backend verteilt Namen per MQTT

03

WLAN-Abbruch mitten im Spiel

Problem

Kurzer WLAN-Ausfall — Controller verliert Zustand und hängt im falschen Screen

Lösung

Reconnect-Loop mit Auto-Resubscribe — letzter State wird nach Reconnect neu gepusht

quiz/connect
04

128×64 OLED — zu wenig Platz

Problem

Alle Spielzustände (Lobby, Multiple Choice, Balkendiagramm, Schätzung) leserlich auf nur 128×64 Pixel unterbringen — ohne den I2C-Bus den MQTT-Loop zu blockieren

Lösung

Pixel-genaue Render-Funktion pro Spielzustand in display.cpp — I2C-Schreibzugriffe nur im loop(), nie in MQTT-Callbacks

12 — Installation

Firmware flashen

flash.py

— lädt Firmware automatisch von GitHub und erkennt den USB-Port
# Repo klonen
git clone https://github.com/XplorodoX/ITS.git
cd ITS
# Abhängigkeit installieren
pip install esptool
# Flashen
python3 flash.py
Browser (kein Python nötig)

firmware.bin von GitHub Releases laden, dann im Browser flashen:

esptool.spacehuhn.com
Manuell (Terminal)

firmware.bin von GitHub Releases laden, dann:

# macOS / Linux
python3 -m esptool --port [port] --baud 115200 write_flash 0x0 firmware.bin
# Windows
python -m esptool --port COM3 --baud 115200 write_flash 0x0 firmware.bin
